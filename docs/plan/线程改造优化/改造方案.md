# LayerBase Async ECS P1–P4 优化设计方案

## 0. 当前问题

当前 benchmark 中，`Async PlainQuery SubmitOnly` 主体代码只做异步 Query 提交，不等待任务完成；等待发生在 `IterationCleanup`。也就是说，这个数据主要反映异步提交路径成本，而不是 ECS Worker 执行成本。

结果显示 `Async PlainQuery SubmitOnly` 大约在数微秒到二十微秒之间，并且每次提交有约 `432 B` 分配。

这说明当前异步提交路径大概率仍然包含：

```text
WorkItem class 分配
接口封装
ConcurrentQueue / 通用队列成本
每 Query Signal
可能的 QueryFlow 临时对象
```

优化目标：

```text
1. 主线程提交 Query 不分配。
2. 主线程提交 Query 不 new WorkItem。
3. 主线程提交 Query 不每次 Signal。
4. Main -> EcsWorker 用 SPSC。
5. EcsWorker -> Main 用 SPSC。
6. Bring 回流使用 Typed ActorEventBatch。
```

不做 P5：

```text
不做轻重 Query 自动判定。
不做 Auto Sync/Async。
不破坏同步模型。
```

# P1：Frame-local SubmissionBatch

## 1.1 目标

把当前：

```text
每个 Query.ForEach 直接投递到跨线程队列
```

改成：

```text
每个 Query.ForEach 只记录到主线程本地 SubmissionBatch
```

真正跨线程发布发生在帧末 Flush。

---

## 1.2 当前模型

```text
Query.ForEach
  -> new WorkItem
  -> Enqueue
  -> Signal
```

问题：

```text
每个 Query 都承担完整异步调度成本。
每个 Query 都可能分配。
每个 Query 都可能触发线程同步。
```

---

## 1.3 新模型

```text
Query.ForEach
  -> Add EcsWorkRecord to current EcsSubmissionBatch
  -> return

Runtime.Pump / Flush 阶段
  -> publish current EcsSubmissionBatch to EcsWorker
  -> Signal once
```

也就是：

```text
Query 级别：本地记录。
Frame 级别：跨线程发布。
```

---

```csharp
    private int _count;

    public EcsJobArena JobArena { get; }

    public int Count => _count;

    public EcsSubmissionBatch(int recordCapacity, int arenaCapacity)
    {

        JobArena = new EcsJobArena(arenaCapacity);

        {
            Array.Resize(ref _records, _records.Length * 2);
        }

        _records[_count++] = record;
    }

    public ReadOnlySpan<EcsWorkRecord> AsSpan()
    {
        return _records.AsSpan(0, _count);
    }

    public void Clear()
    {
        _count = 0;
        JobArena.Reset();
    }
}
```

## 1.7 Runtime.Pump 中 Flush

在 Layer/Service 业务执行之后 Flush：

```csharp
private void PumpCore(float deltaTime)
{
    // 1. Drain 上一批 ECS 结果
    EcsScheduler.DrainResults(EcsOptions.MaxResultsDrainPerPump);

    // 2. 普通主线程逻辑
    _timer?.Tick(deltaTime, _timerSink!);
    DelayManager?.Tick(deltaTime);
    _postIngress.DrainTo(_scheduler);
    _scheduler.Pump();

    // 3. Service / Layer Pump，这里会调用 Query.ForEach
    _chain?.Pump(deltaTime);

    // 4. Flush 本帧记录的 ECS work
    EcsScheduler.FlushSubmissions();

    // 5. Actor Pump
    Actors.Pump(...);
}
```

这里的语义很明确：

```text
Async Query 在本帧被记录。
Flush 后交给 EcsWorker。
结果下一次 DrainResults 时回主线程。
```

# P2：双向 SPSC Batch Ring

## 2.1 目标

你的通信模型不是 MPSC，而是：

```text
Main -> EcsWorker：单生产者，单消费者
EcsWorker -> Main：单生产者，单消费者
```

所以热路径应该用双向 SPSC，而不是 `ConcurrentQueue`。

---

## 2.2 两条通道

```text
SPSC A:
  Main Thread produces EcsSubmissionBatch
  EcsWorker consumes EcsSubmissionBatch

SPSC B:
  EcsWorker produces EcsResultBatch
  Main Thread consumes EcsResultBatch
```

---

## 2.3 新增类型

目录建议：

```text
LayerBase/ECS/Runtime/Queues/
  SpscRing.cs
  PaddedInt.cs
```

```csharp
[StructLayout(LayoutKind.Explicit, Size = 64)]
internal struct PaddedInt
{
    [FieldOffset(0)]
    public int Value;
}
```

```csharp
internal sealed class SpscRing<T>
    where T : class
{
    private readonly T?[] _buffer;
    private readonly int _mask;

    private PaddedInt _head;
    private PaddedInt _tail;

    public SpscRing(int capacityPowerOfTwo)
    {
        if ((capacityPowerOfTwo & (capacityPowerOfTwo - 1)) != 0)
        {
            throw new ArgumentException("Capacity must be power of two.");
        }

        _buffer = new T?[capacityPowerOfTwo];
        _mask = capacityPowerOfTwo - 1;
    }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public bool TryEnqueue(T item)
    {
        int tail = _tail.Value;
        int next = tail + 1;

        int head = Volatile.Read(ref _head.Value);

        if (next - head > _buffer.Length)
        {
            return false;
        }

        _buffer[tail & _mask] = item;

        Volatile.Write(ref _tail.Value, next);

        return true;
    }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public bool TryDequeue(out T? item)
    {
        int head = _head.Value;

        int tail = Volatile.Read(ref _tail.Value);

        if (head == tail)
        {
            item = null;
            return false;
        }

        int index = head & _mask;
        item = _buffer[index];
        _buffer[index] = null;

        Volatile.Write(ref _head.Value, head + 1);

        return true;
    }
}
```

这里 `T` 用 class 是为了投递 Batch 引用。

也就是说跨线程队列里不是每个 Query 一个 record，而是每帧一个 batch 引用：

```text
SPSC.Enqueue(EcsSubmissionBatch)
```

## 2.5 FlushSubmissions

```csharp
public void FlushSubmissions()
{
    EcsSubmissionBatch batch = _currentSubmissionBatch;

    if (batch.Count == 0)
    {
        return;
    }

    if (!_mainToEcs.TryEnqueue(batch))
    {
        HandleSubmissionQueueFull(batch);
        return;

    _currentSubmissionBatch = _submissionBatchPool.Rent();
```

```csharp
           _ecsToMain.TryDequeue(out EcsResultBatch? batch))
```

# P3：EcsWorkRecord + JobArena + ExecutorId

## 3.1 目标


## 3.3 JobArena

目录：

```text
LayerBase/ECS/Runtime/Submission/
  EcsJobArena.cs
```

```csharp
internal sealed class EcsJobArena
{
    private byte[] _buffer;
    private int _offset;

    public EcsJobArena(int capacity)
    {
        _buffer = new byte[capacity];
    }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public int Store<TJob>(in TJob job)
        where TJob : struct
    {
        int size = Unsafe.SizeOf<TJob>();
        int offset = Align(_offset, Math.Min(size, 16));

        EnsureCapacity(offset + size);

        Unsafe.WriteUnaligned(
            ref _buffer[offset],
            job);

        _offset = offset + size;
        return offset;
    }

    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public ref TJob Get<TJob>(int offset)
        where TJob : struct
    {
        return ref Unsafe.As<byte, TJob>(ref _buffer[offset]);
    }

    public void Reset()
    {
        _offset = 0;
    }

    private static int Align(int value, int alignment)
    {
        return (value + alignment - 1) & ~(alignment - 1);
    }

    private void EnsureCapacity(int required)
    {
        if (required <= _buffer.Length)
        {
            return;
        }

        Array.Resize(ref _buffer, Math.Max(required, _buffer.Length * 2));
    }
}
```

# P4：Typed ActorEventBatch

## 4.1 目标

优化 Bring 回流：

```text
EcsWorker -> Main -> ActorWorld
```

不要每个 ActorEvent 一个 command object。

改成：

```text
按事件类型批量回流。
```

---

## 4.2 当前低效模型

如果使用：

```csharp
interface IActorEventCommand
{
    void PostTo(ActorWorld actorWorld);
}
```

然后每个事件：

```csharp
new ActorEventCommand<TEvent>(actorId, value)
```

问题是：

```text
每个事件一个对象。
每个事件一次 interface dispatch。
事件数据分散在堆上。
GC 压力大。
```

---

## 4.3 新模型

```text
ActorEventBatch<TEvent>
  ActorId[]
  TEvent[]
  Count
```

```csharp
internal interface IEcsResultBatch
{
    int Count { get; }

    void ApplyToMainThread(LayerRuntime runtime);

    void Clear();
}
```

```csharp
internal sealed class ActorEventBatch<TEvent> : IEcsResultBatch
    where TEvent : struct, IActorEvent
{
    private ActorId[] _actorIds;
    private TEvent[] _events;
    private int _count;

    public int Count => _count;

    public ActorEventBatch(int capacity)
    {
        _actorIds = new ActorId[capacity];
        _events = new TEvent[capacity];
    }

    public void Add(ActorId actorId, in TEvent value)
    {
        if (_count >= _events.Length)
        {
            Grow();
        }

        _actorIds[_count] = actorId;
        _events[_count] = value;
        _count++;
    }

    public void ApplyToMainThread(LayerRuntime runtime)
    {
        ActorWorld actors = runtime.Actors;

        for (int i = 0; i < _count; i++)
        {
            actors.PostTo(_actorIds[i], in _events[i]);
        }
    }

    public void Clear()
    {
        _count = 0;
    }

    private void Grow()
    {
        int newLength = _events.Length * 2;
        Array.Resize(ref _actorIds, newLength);
        Array.Resize(ref _events, newLength);
    }
}
```

```csharp
ActorEventBatch<DamageEvent> damageBatch =
    results.GetActorEventBatch<DamageEvent>();

ActorEventBatch<HitViewEvent> hitViewBatch =
    results.GetActorEventBatch<HitViewEvent>();
```

Success 时：

```csharp
damageBatch.Add(actorId, in damage);
hitViewBatch.Add(actorId, in hitView);
```

## 4.7 Batch Pool

```csharp
internal static class ActorEventBatchPool<TEvent>
    where TEvent : struct, IActorEvent
{
    private static readonly ConcurrentBag<ActorEventBatch<TEvent>> s_pool = new();

    public static ActorEventBatch<TEvent> Rent()
    {
        if (s_pool.TryTake(out var batch))
        {
            return batch;
        }

        return new ActorEventBatch<TEvent>(capacity: 1024);
    }

    public static void Return(ActorEventBatch<TEvent> batch)
    {
        batch.Clear();
        s_pool.Add(batch);
    }
}
```

第一版用 `ConcurrentBag` 简单可靠。

后续可以优化成：

```text
EcsWorker local pool
Main return queue
SPSC returned batch pool
```

## 4.8 P4 验收标准

```text
1. Async Bring 不再每 ActorEvent new command object。
2. Async Bring 回流按事件类型批量。
3. DrainResults 只做 batch 级接口调用。
4. ActorEvent 数据连续存储。
5. Bring 大量事件时 GC 显著下降。
```

# 5. P1–P4 总流程

最终流程：

```text
Main Thread:
  Query.ForEach
    -> RecordPlainQuery / RecordBringQuery
    -> job copy to JobArena
    -> EcsWorkRecord append to current EcsSubmissionBatch

Frame Flush:
  EcsSubmissionBatch -> SPSC mainToEcs ring
  Signal once

EcsWorker:
  Dequeue EcsSubmissionBatch
  For each EcsWorkRecord:
    ExecutorRegistry.Execute
      PlainQuery -> 修改 ECS
      BringQuery -> 生成 ActorEventBatch<TEvent>

EcsWorker Result:
  EcsResultBatch -> SPSC ecsToMain ring

Main Thread:
  DrainResults
    -> ActorEventBatch<TEvent>.ApplyToMainThread
    -> ActorWorld.PostTo
```

---

# 6. 不做 P5 的原因

不做：

```text
轻任务 Sync，重任务 Async 的自动判断。
```

原因：

```text
1. 会破坏模式一致性。
2. 同一个 Query 的结果可见时间可能变化。
3. “轻量/重量”难以稳定定义。
4. Benchmark 环境和真实运行环境不同。
5. 用户会难以推断数据何时可见。
```

保留清晰模型：

```text
Sync 模式：
  Query 立即执行，结果立即可见。

Async 模式：
  Query 投递到 EcsWorker，结果异步可见。
```

这比自适应策略更适合框架早期。

# 7. 推荐实施顺序

## Commit 1：P1 SubmissionBatch

```text
新增 EcsSubmissionBatch。
```

```text
Main -> EcsWorker 改 SPSC batch ring。

```

目标：

```text
跨线程通信按 batch 走。
```

```text

```

目标：

```text

```

---

```text
Async Bring 回流从 command object 改成 ActorEventBatch<TEvent>。
DrainResults 批量 PostTo ActorWorld。
```

目标：

```text
大量 ActorEvent 回流时降低分配和接口分发。
```

# 9. 最终结论

P1–P4 的核心是：

```text
P1：不要每 Query 跨线程投递，先记录到本地 batch。
P2：Main/EcsWorker 双向通信用 SPSC batch ring。
P3：不要 WorkItem class，改成 EcsWorkRecord + JobArena + ExecutorId。
P4：不要 ActorEvent command object，改成 Typed ActorEventBatch<TEvent>。
```
