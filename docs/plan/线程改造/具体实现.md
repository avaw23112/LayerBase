# LayerBase 多线程运行时核心落地设计

## 0. 当前代码里的关键落点

先确认现有结构。

`LayerRuntime` 当前拥有 `EventCenter`、`ActorWorld`、`Services`，并在构造函数里调用 `InitializeEcsWorld()` 创建 ECS World。

`LayerRuntime.ECS.cs` 当前非常薄，只是创建 Arch `World`，并执行 `EcsWorld.BindRuntime(this)`。

`ServiceECSExtensions.Query<T...>` 当前只是通过 `ECSWorld(service).Query<T...>()` 返回 ProjectionQueryFlow；直接获取 `ECSWorld()` 被注释为 Advanced API，普通业务优先使用 `Query`。

当前 `ProjectionQueryFlow` 的普通 Query 会直接调用 `ProjectionExecutor.ForEach(...)`，Bring Query 会走 `.Bring<TEvent>().ForEach(...).Batch().Post()`，最后调用 `ProjectionExecutor.Post(...)`。

当前 `ProjectionExecutor` 会直接遍历 `query.GetChunkIterator()` 执行 ECS Query；Bring 分支会拿到 `ActorWorld actorWorld = world.Runtime.Actors`，然后 `ProjectionBatchBuffer<TEvent>.PostTo(actorWorld)`。

当前跨线程普通事件已经有 `PostIngressQueue`，它用 `ConcurrentQueue<IIngressPostItem>`，允许任意线程 enqueue，Runtime.Pump 中唯一消费者 drain 到 `PostScheduler`。

所以设计的核心就是：

```text id="3zjzjq"
不要重写 Query API。
不要重写 Actor 模型。
新增 EcsDomain/EcsScheduler 包住 EcsWorld。
让 ProjectionQueryFlow/ProjectionExecutor 在 Async 模式下不直接执行，而是生成 WorkItem 入队。
让 Bring 的 ActorEvent 不再由 EcsWorker 直接 PostTo(actorWorld)，而是写入 ActorEventCommandBuffer，再由主线程 Flush。
```

## 3.1 SyncEcsScheduler

同步模式下，不开线程，不入队，直接执行：

```csharp id="y9uef8"
internal sealed class SyncEcsScheduler : IEcsScheduler
{
    private readonly LayerRuntime _runtime;
    private readonly World _world;

    public SyncEcsScheduler(LayerRuntime runtime, World world)
    {
        _runtime = runtime;
        _world = world;
    }

    public EcsExecutionMode Mode => EcsExecutionMode.Sync;

    public void Schedule(IEcsWorkItem item)
    {
        try
        {
            item.Execute(_world, _runtime.EcsResultQueue);
        }
        catch (Exception ex)
        {
            _runtime.EcsResultQueue.Enqueue(new EcsWorkFailedResult(item.DebugName, ex));
        }
    }

    public EcsDrainStats DrainResults(int maxCount)
    {
        return _runtime.EcsResultQueue.DrainToMainThread(_runtime, maxCount);
    }

    public void Start() { }

    public void Stop() { }

    public void Dispose() { }
}
```

这里有一个设计选择：

```text id="fe2p92"
Sync 模式是否立即把 ActorEvent 投给 ActorWorld？
```

为了行为一致，建议 Sync 模式也走 `EcsResultQueue`，由 Runtime.Pump 的固定阶段统一 Drain。这样 Sync/Async 的事件到达语义更接近。

## 3.2 AsyncEcsScheduler

```csharp id="g5s759"
internal sealed class AsyncEcsScheduler : IEcsScheduler
{

    private readonly World _world;

    }
```

# 4. 线程创建设计

`EcsWorker` 第一版用一个专用 `Thread`，不要用 ThreadPool。原因：

```text id="jr60my"
1. EcsWorld 有线程所有权。
2. 长生命周期数据域适合固定线程。
3. 避免 ThreadPool 抢占和调度不稳定。
4. 便于调试和 Profiler 标识。
```

实现：

```csharp id="9x0nhu"
internal sealed class EcsWorker
{
    private readonly LayerRuntime _runtime;
    private readonly World _world;
    private readonly EcsWorkQueue _workQueue;
    private readonly EcsResultQueue _resultQueue;
    private readonly EcsRuntimeOptions _options;
    private readonly AutoResetEvent _signal = new(false);

    private Thread? _thread;
    private volatile bool _running;
    private int _ecsThreadId;

    public EcsWorker(
        LayerRuntime runtime,
        World world,
        EcsWorkQueue workQueue,
        EcsResultQueue resultQueue,
        EcsRuntimeOptions options)
    {
        _runtime = runtime;
        _world = world;
        _workQueue = workQueue;
        _resultQueue = resultQueue;
        _options = options;
    }

    public void Start()
    {
        if (_running)
        {
            return;
        }

        _running = true;
        _thread = new Thread(Run)
        {
            IsBackground = true,
            Name = _options.WorkerName
        };
        _thread.Start();
    }

    public void Signal()
    {
        _signal.Set();
    }

    public void Stop()
    {
        _running = false;
        _signal.Set();
        _thread?.Join();
        _thread = null;
    }

    private void Run()
    {
        _ecsThreadId = Environment.CurrentManagedThreadId;
        EcsThreadGuard.Bind(_runtime.Id, _ecsThreadId);

        while (_running)
        {
            bool didWork = false;
            int processed = 0;

            while ((_options.MaxWorkItemsPerWake <= 0 || processed < _options.MaxWorkItemsPerWake)
                   && _workQueue.TryDequeue(out IEcsWorkItem? item))
            {
                didWork = true;
                processed++;

                try
                {
                    item.Execute(_world, _resultQueue);
                }
                catch (Exception ex)
                {
                    _resultQueue.Enqueue(new EcsWorkFailedResult(item.DebugName, ex));
                }
            }

            if (!didWork)
            {
                _signal.WaitOne();
            }
        }

        EcsThreadGuard.Unbind(_runtime.Id);
    }
}
```

`EcsThreadGuard` 用于 Debug/Analyzer 辅助：

```csharp id="gp5kej"
internal static class EcsThreadGuard
{
    private static readonly Dictionary<int, int> RuntimeToThreadId = new();
    private static readonly object Gate = new();

    public static void Bind(int runtimeId, int threadId)
    {
        lock (Gate)
        {
            RuntimeToThreadId[runtimeId] = threadId;
        }
    }

    public static void Unbind(int runtimeId)
    {
        lock (Gate)
        {
            RuntimeToThreadId.Remove(runtimeId);
        }
    }

    public static bool IsEcsThread(int runtimeId)
    {
        lock (Gate)
        {
            return RuntimeToThreadId.TryGetValue(runtimeId, out int id)
                   && id == Environment.CurrentManagedThreadId;
        }
    }
}
```

# 5. MPSC 队列设计

你已经有 `PostIngressQueue`，它的设计说明很成熟：任意线程 enqueue，Runtime.Pump 唯一消费者 drain 到 PostScheduler。

ECS 可以照这个模式做，但分两个队列。

## 5.1 Main/Many -> ECS：EcsWorkQueue

```csharp id="u35y9s"
internal sealed class EcsWorkQueue
{
    private readonly ConcurrentQueue<IEcsWorkItem> _queue = new();

    public void Enqueue(IEcsWorkItem item)
    {
        _queue.Enqueue(item);
    }

    public bool TryDequeue(out IEcsWorkItem? item)
    {
        return _queue.TryDequeue(out item);
    }

    public void Clear()
    {
        while (_queue.TryDequeue(out _))
        {
        }
    }
}
```

第一版用 `ConcurrentQueue<T>`，理由：

```text id="3rpgwb"
1. 项目已有 PostIngressQueue 使用 ConcurrentQueue。
2. 先验证架构，不提前写复杂 lock-free ring buffer。
3. ECS WorkItem 是粗粒度任务，不是每组件一个任务，队列开销不是第一瓶颈。
```

第二版再优化成：

```text id="8vfpbt"
bounded MPSC ring buffer
ArrayPool-backed queue
backpressure/reject policy
```

## 5.2 ECS -> Main：EcsResultQueue

```csharp id="13l5ln"
internal sealed class EcsResultQueue
{
    private readonly ConcurrentQueue<IEcsResultItem> _queue = new();

    public void Enqueue(IEcsResultItem result)
    {
        _queue.Enqueue(result);
    }

    public EcsDrainStats DrainToMainThread(
        LayerRuntime runtime,
        int maxCount)
    {
        int drained = 0;
        int failed = 0;

        while ((maxCount <= 0 || drained < maxCount)
               && _queue.TryDequeue(out IEcsResultItem? item))
        {
            try
            {
                item.Apply(runtime);
            }
            catch (Exception ex)
            {
                failed++;
                runtime.ReportLayerEventError(
                    -1,
                    "EcsResultQueue",
                    item.DebugName,
                    ex);
            }

            drained++;
        }

        return new EcsDrainStats(drained, failed);
    }

    public void Clear()
    {
        while (_queue.TryDequeue(out _))
        {
        }
    }
}
```

# 6. ActorEventCommandBuffer 设计

当前 Bring 执行器会租 `ProjectionBatchBuffer<TEvent>`，然后直接 `batch.PostTo(actorWorld)`。

异步模式下不能这样，因为 EcsWorker 不能直接碰 `ActorWorld`。

所以要把：

```text id="cs65oy"
ProjectionBatchBuffer<T>.PostTo(actorWorld)
```

改为：

```text id="i6j7tp"
ProjectionBatchBuffer<T> -> ActorEventCommandBuffer -> EcsResultQueue -> Main Thread -> PostTo(actorWorld)
```

第一版可以这样设计：

```csharp id="xrkwd7"
internal sealed class ActorEventCommandBuffer : IEcsResultItem, IDisposable
{
    private readonly List<IActorEventCommand> _commands = new();

    public string DebugName => "ActorEventCommandBuffer";

    public void Add<TEvent>(ActorId actorId, in TEvent value)
        where TEvent : struct
    {
        _commands.Add(new ActorEventCommand<TEvent>(actorId, value));
    }

    public void Apply(LayerRuntime runtime)
    {
        ActorWorld actorWorld = runtime.Actors;

        for (int i = 0; i < _commands.Count; i++)
        {
            _commands[i].PostTo(actorWorld);
        }
    }

    public void Dispose()
    {
        _commands.Clear();
    }
}

internal interface IActorEventCommand
{
    void PostTo(ActorWorld actorWorld);
}

internal readonly struct ActorEventCommand<TEvent> : IActorEventCommand
    where TEvent : struct
{
    private readonly ActorId _actorId;
    private readonly TEvent _value;

    public ActorEventCommand(ActorId actorId, TEvent value)
    {
        _actorId = actorId;
        _value = value;
    }

    public void PostTo(ActorWorld actorWorld)
    {
        actorWorld.PostTo(_actorId, in _value);
    }
}
```

这版会有 interface/list 分配，第一版用于验证模型可以接受。优化版做成：

```text id="igk8ph"
per-event-type typed batch
ActorEventCommandBatch<TEvent>
ArrayPool<T>
无装箱命令列表
```

更贴近当前 `ProjectionBatchBuffer<TEvent>`。

优化版：

```csharp id="e2u56a"
internal sealed class ActorEventCommandBatch<TEvent> : IEcsResultItem
    where TEvent : struct
{
    private ProjectionBatchBuffer<TEvent> _batch;

    public string DebugName => $"ActorEventCommandBatch<{typeof(TEvent).Name}>";

    public void Add(ActorId actorId, in TEvent value)
    {
        _batch.Add(actorId, in value);
    }

    public void Apply(LayerRuntime runtime)
    {
        _batch.PostTo(runtime.Actors);
    }
}
```

但因为 `ProjectionBatchBuffer<TEvent>` 现在可能是 ref struct / pool 语义，需要检查它能不能跨线程保存。如果不能，新增 `ActorEventCommandBatch<TEvent>` 自己维护 `ActorId[] + TEvent[]`。

## 7.2 Bring Projection WorkItem

```csharp id="iwfb0t"
internal sealed class BringProjectionWorkItem<TJob, T1, T2, TEvent0> : IEcsWorkItem
    where TJob : struct, IProjectionJob2x1<T1, T2, TEvent0>
    where TEvent0 : struct
{
    private readonly Query _query;
    private readonly ProjectionPredicate<T1, T2>? _predicate;
    private TJob _job;

    public BringProjectionWorkItem(
        Query query,
        ProjectionPredicate<T1, T2>? predicate,
        in TJob job)
    {
        _query = query;
        _predicate = predicate;
        _job = job;
    }

    public string DebugName => $"BringProjection<{typeof(TEvent0).Name}>";

    public void Execute(World world, EcsResultQueue results)
    {
        ActorEventCommandBatch<TEvent0> batch =
            ActorEventCommandBatch<TEvent0>.Rent();

        try
        {
            ProjectionExecutor2<T1, T2>.ExecuteBring(
                world,
                _query,
                _predicate,
                ref _job,
                ref batch);

            if (batch.Count > 0)
            {
                results.Enqueue(batch);
                batch = default;
            }
        }
        finally
        {
            batch?.Dispose();
        }
    }
}
```

核心是：`ExecuteBring` 不能直接拿 `ActorWorld` 并 `PostTo`，只能写 batch。

# 8. 修改 ProjectionQueryFlow.tt

当前 `ProjectionQueryFlow.tt` 的普通 Query 直接调用：

```csharp id="2p2epc"
ProjectionExecutor<c>.ForEach(_world, _query, _predicate, ref job);
```

Bring Job 的 `.Post()` 直接调用：

```csharp id="55k9m9"
ProjectionExecutor<c>.Post<TEvent0, TJob>(_world, _query, _predicate, ref job);
```

需要改为：

```csharp id="ulf7pr"
public void ForEach<TJob>(ref TJob job)
    where TJob : struct, IQueryJob<T...>
{
    ProjectionExecutor<c>.ForEach(
        _world,
        _query,
        _predicate,
        ref job);
}
```

`ProjectionExecutor.ForEach` 内部再判断 scheduler：

```csharp id="4aesvo"
public static void ForEach<TJob>(
    World world,
    Query query,
    ProjectionPredicate<T...>? predicate,
    ref TJob job)
    where TJob : struct, IQueryJob<T...>
{
    IEcsScheduler scheduler = world.Runtime.EcsScheduler;

    if (scheduler.Mode == EcsExecutionMode.Sync)
    {
        ExecutePlain(world, query, predicate, ref job);
        return;
    }

    scheduler.Schedule(
        new PlainQueryWorkItem<TJob, T...>(
            query,
            predicate,
            in job));
}
```

Bring `.Post()` 类似：

```csharp id="1dwlgv"
public static void Post<TEvent0, TJob>(
    World world,
    Query query,
    ProjectionPredicate<T...>? predicate,
    ref TJob job)
    where TEvent0 : struct
    where TJob : struct, IProjectionJob...
{
    IEcsScheduler scheduler = world.Runtime.EcsScheduler;

    if (scheduler.Mode == EcsExecutionMode.Sync)
    {
        ExecuteBringAndPostOnMain(world, query, predicate, ref job);
        return;
    }

    scheduler.Schedule(
        new BringProjectionWorkItem<TJob, T..., TEvent0>(
            query,
            predicate,
            in job));
}
```

这里要注意一个关键点：

```text id="myfjtm"
如果 Sync 模式为了完全复用当前行为，可以继续 ExecuteBringAndPostOnMain。
Async 模式必须 ExecuteBringToCommandBuffer。
```

# 9. 修改 ProjectionExecutor.tt

当前 `ProjectionExecutor` 把三件事混在一起：

```text id="wu4i1t"
1. 遍历 ECS Query。
2. RefreshProjectedActorInterest。
3. ProjectionBatchBuffer.PostTo(actorWorld)。
```

异步改造需要拆成：

```text id="2cr2un"
ExecutePlain：
  只做普通 Query 遍历。

ExecuteBringToActorWorld：
  Sync 模式可保留当前行为。

ExecuteBringToCommandBuffer：
  Async 模式使用，生成 ActorEventCommandBatch，不碰 ActorWorld 内部投递。
```

对 Bring 来说，仍可能需要 `RefreshProjectedActorInterest`。这里有一个核心决策：

```text id="hl59bn"
ProjectedActorRef 的 Touch/Ensure 是否可以在 EcsWorker 执行？
```

当前 `RefreshProjectedActorInterest(world, actorWorld, entity, ref actorRef, nowTicks)` 需要 `ActorWorld`。

异步模式下不能让 EcsWorker 直接访问 `ActorWorld`，所以这里必须改。

有两种方案。

---

## 9.1 方案 A：EcsWorker 只生成 ProjectionCommand，主线程 Touch/Ensure Actor

异步 Bring 执行时：

```text id="25e7br"
EcsWorker:
  执行 Query
  得到 entity + ProjectedActorRef + ProjectResult
  不 RefreshProjectedActorInterest
  生成 ProjectionActorCommand:
    entity
    projected actor meta / actor type
    event payload

MainThread:
  Drain ProjectionActorCommand
  RefreshProjectedActorInterest
  如果 alive，再 Post ActorEvent
```

优点：

```text id="sen8iy"
ActorWorld 绝不被 EcsWorker 碰。
线程模型最干净。
```

缺点：

```text id="771oxu"
ProjectedActorRef 的 ActorId 写回在主线程发生。
如果 EcsWorker 同时还拥有 EcsWorld，会出现主线程写 ECS 的 ProjectedActorRef。
```

这违背 “EcsWorld 只归 EcsWorker” 原则。

---

## 9.2 方案 B：拆分 ProjectedActorRef 与 ActorWorld 触达

把 `ProjectedActorRef` 的 ECS 部分交给 EcsWorker，Actor 创建/投递请求变成主线程命令：

```text id="xaafzz"
EcsWorker:
  读取/更新 ProjectedActorRef 中的兴趣状态、过期时间等 ECS 字段。
  如果需要 ActorId 但当前无 ActorId：
    生成 EnsureProjectedActorCommand。
  如果已有 ActorId：
    生成 ActorEventCommand。

MainThread:
  执行 EnsureProjectedActorCommand，创建/租用 Actor。
  生成 ActorId 后，需要回写 ECS。
```

但回写 ECS 又要发回 EcsWorker。

这会变成两阶段，复杂。

---

## 9.3 第一版推荐：Async Bring 要求 ProjectedActorRef 已绑定 ActorId

为了第一版落地，推荐先做更小闭环：

```text id="fi8wl8"
异步 ECS 模式下：
  Bring Query 可以给已有 ActorId 的 ProjectedActorRef 投递事件。
  ActorId 无效时，不在 EcsWorker 内 Ensure Actor。
  Ensure/TouchProjectedActor 仍由主线程已有 Pump/Sweep/Projection 初始化路径维护。
```

也就是说，第一版先不要把 `RefreshProjectedActorInterest` 搬进 EcsWorker。

Bring Async 的第一版规则：

```text id="ljiyj5"
ProjectResult.Fail：
  不 Post。

ProjectResult.Touch：
  记录 Touch 请求，主线程处理或第一版跳过。

ProjectResult.Success：
  如果 actorRef.ActorId 有效，生成 ActorEventCommand。
  如果 ActorId 无效，生成 ProjectionMissResult 或跳过并统计。
```

这牺牲一部分自动 Ensure 能力，但避免第一版线程模型炸裂。

第二版再做 `ProjectedActorBridge`：

```text id="61fcqd"
EcsWorker -> Main：EnsureActorRequest
Main -> EcsWorker：BindActorIdCommand
```

# 10. Runtime.Pump 修改

当前 PumpCore 顺序是：

```text id="vws3uu"
1. Timer tick
2. Delay tick
3. FixedUpdate accumulator
4. Post ingress drain
5. Post pump + layer pump + actor pump
6. EcsWorld.SweepProjectedActors()
```

可从代码看到 `_postIngress.DrainTo(...)` 后，`_scheduler.Pump()`、`_chain.Pump(deltaTime)`、`Actors.Pump(...)`，最后 `EcsWorld.SweepProjectedActors()`。

建议改成：

```csharp id="ta3iq4"
private void PumpCore(float deltaTime)
{
    // 0. Drain Worker events -> PostScheduler
    WorkerRuntime?.DrainEventsTo(_scheduler, ...);

    // 1. Drain Ecs results -> Actor/Event
    EcsScheduler?.DrainResults(EcsOptions.MaxResultsDrainPerPump);

    // 2. Time tick
    _timer?.Tick(deltaTime, _timerSink!);

    // 3. Delay tick
    if (_chain != null && _chain.HasAnyDelay)
        DelayManager?.Tick(deltaTime);

    // 4. FixedUpdate
    ...

    // 5. PostFromAnyThread ingress
    _postIngress.DrainTo(...);

    // 6. PostScheduler Pump
    PostPumpStats postStats = _scheduler?.Pump() ?? default;

    // 7. Layer Pump：这里会调用 Query，Async 模式下只是入队
    _chain?.Pump(deltaTime);

    // 8. Actor Pump：处理 ECS/Bring 回流后的 ActorEvent
    Actors.Pump(...);

    // 9. ECS projection sweep
    if (EcsScheduler.Mode == EcsExecutionMode.Sync)
    {
        EcsWorld.SweepProjectedActors();
    }
    else
    {
        // Async 模式下 sweep 不能主线程直接扫 EcsWorld。
        // 需要变成 EcsWorkItem 或暂时禁用/迁移。
        EcsScheduler.Schedule(new SweepProjectedActorsWorkItem());
    }
}
```

注意最后这点很重要：当前 `EcsWorld.SweepProjectedActors()` 在主线程执行。
如果 Async 模式下 EcsWorld 归 EcsWorker，这里必须迁移。

# 12. 源生成器设计

## 12.1 当前 QueryBringGenerator 的问题

当前生成器会生成 Job：

```text id="dv11n5"
private readonly SelfType _self;
```

然后在 `Execute` 里调用：

```text id="1tj0h3"
_self.OnXxx(...)
```

这在生成器代码里能看到：生成 `__XxxJob(this)`，Job 内保存 `_self`，Execute 调 `_self.methodName(...)`。

异步模式下，如果 EcsWorker 执行这个 Job，就会跨线程访问 Service/Context 实例。

这是最大风险。

---

## 12.2 第一版生成器策略：Analyzer 限制

第一版不立刻重构生成器，只加 Analyzer：

```text id="lf7mdo"
AsyncECS 模式启用时：
  [Query] 方法不得访问实例字段。
  [Query] 方法不得访问实例属性。
  [Query] 方法不得调用实例方法。
  [Query] 方法不得访问 this。
  [Query] 方法只能使用参数。
```

这样虽然 Job 结构里仍有 `_self`，但 `_self.OnXxx(...)` 调用的方法体只使用参数，风险可控。

不过严格来说，调用实例方法本身也会访问 `_self`。因此第一版可以接受但不完美。更安全是第二版。

---

## 12.3 第二版生成器策略：生成 static Execute

推荐长期改为：

```csharp id="aj8npf"
[Query]
private static void OnMove(ref Position position, in Velocity velocity)
{
    position.Value += velocity.Value;
}
```

生成：

```csharp id="3k3e5n"
private readonly struct __MoveJob : IQueryJob<Position, Velocity>
{
    public void Execute(Entity entity, ref Position position, ref Velocity velocity)
    {
        OnMove(ref position, in velocity);
    }
}
```

没有 `_self`。

如果需要输入参数：

```csharp id="ejqwk2"
public void Move(float deltaTime)
{
    var job = new __MoveJob(deltaTime);
    this.Query<Position, Velocity>().ForEach(ref job);
}
```

用户写：

```csharp id="z7ooew"
[Query]
[EntryPoint("Move")]
private static void OnMove(
    float deltaTime,
    ref Position position,
    in Velocity velocity)
{
    position.Value += velocity.Value * deltaTime;
}
```

这需要扩展 QueryBringGenerator 支持“非组件输入参数”。当前生成器只接受 Entity、组件参数、Bring Event 参数；其他参数会 return null。

新增规则：

```text id="6nycp3"
组件参数：
  ref / in IComponent

Entity 参数：
  Arch.Core.Entity

Bring 参数：
  ref TEvent，位于末尾

Input 参数：
  普通值类型参数，位于组件参数之前或通过 EntryPoint 参数传入
```

# 13. Worker 模型放置与实现

Worker 不属于 ECS，建议放 `LayerBase/Worker/`，因为它服务于资源、存档、AI、寻路、普通 Event 回流。

核心接口：

```csharp id="li7rq2"
public interface IWorkerEventJob<TInput, TEvent>
    where TInput : struct
    where TEvent : struct
{
    TEvent Execute(in TInput input);
}
```

`WorkerRuntime`：

```csharp id="ctz4j3"
public sealed class WorkerRuntime : IDisposable
{
    private readonly WorkerJobQueue _jobs = new();
    private readonly WorkerEventQueue _events = new();
    private readonly Thread[] _threads;
    private volatile bool _running;

    public WorkerHandle RunEventJob<TJob, TInput, TEvent>(
        in TJob job,
        in TInput input)
        where TJob : struct, IWorkerEventJob<TInput, TEvent>
        where TInput : struct
        where TEvent : struct
    {
        var handle = AllocateHandle();
        _jobs.Enqueue(new WorkerJobItem<TJob, TInput, TEvent>(
            handle,
            job,
            input,
            _events));
        return handle;
    }

    public void DrainEventsTo(PostScheduler scheduler, int maxCount)
    {
        _events.DrainTo(scheduler, maxCount);
    }
}
```

`WorkerJobItem`：

```csharp id="5qg9la"
internal sealed class WorkerJobItem<TJob, TInput, TEvent> : IWorkerJobItem
    where TJob : struct, IWorkerEventJob<TInput, TEvent>
    where TInput : struct
    where TEvent : struct
{
    private readonly WorkerHandle _handle;
    private TJob _job;
    private TInput _input;
    private readonly WorkerEventQueue _events;

    public void Execute()
    {
        try
        {
            TEvent result = _job.Execute(in _input);
            _events.Enqueue(result);
        }
        catch (Exception ex)
        {
            _events.Enqueue(new WorkerJobFailedEvent(_handle, typeof(TJob), ex));
        }
    }
}
```

Worker 回流普通 Event，复用 PostScheduler 预算，不进入 ActorEventCommandBuffer。

# 16. 第一版关键取舍

```text id="6ewnkr"
1. WorkItem 是 class，会有每次 Query 提交分配。
2. MPSC 使用 ConcurrentQueue。
```

```text id="9yfnqw"
1. WorkItem 池化。

3. QueryGenerator 支持 static query + 显式输入参数，去掉 _self。
4. ProjectedActor Ensure 双向命令化。
5. ActorEventCommandBatch<TEvent> 无装箱。
```

# 17. 最核心风险

最大的技术风险不是线程创建，也不是队列，而是这个：

```text id="9ochsl"
当前 QueryBringGenerator 生成的 Job 会持有 _self。
Async 模式下 EcsWorker 执行 job.Execute，会跨线程访问业务对象。
```

所以落地时必须二选一：

```text id="awdxyn"
短期：
  Analyzer 禁止 Query 方法访问实例状态。

长期：
  改生成器，让 Async-safe Query 生成纯静态 Job，不持有 _self。
  详情看Query源生成器修改方案
```

这是整个设计成败的关键。

# 18. 最终架构图

```text id="top93i"
Main Thread
  ├─ Context / Service
  │    ├─ Query.ForEach(...)     -> PlainEcsQueryWorkItem
  │    ├─ Query.Bring(...).Post -> BringProjectionWorkItem
  │    └─ Worker.RunEventJob    -> WorkerJobItem

  ├─ ActorWorld / ActorScheduler
  └─ Runtime.Pump
       ├─ Drain WorkerEventQueue -> PostScheduler
       ├─ Drain EcsResultQueue   -> ActorWorld
       ├─ Pump PostScheduler
       ├─ Pump Layer / Service
       └─ Pump Actor

EcsWorker Thread
  └─ EcsWorld
       ├─ Execute Plain Query
       ├─ Execute Bring Query
       └─ Produce ActorEventCommandBuffer

WorkerPool
  ├─ IO
  ├─ Save Encode/Decode
```


这就是我建议的落地路线。
