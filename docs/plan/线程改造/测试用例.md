# LayerBase Static Query + Async ECS 测试用例修改方案

## 0. 测试修改目标

本次改造包含两个变化：

```text id="7wi8oz"
1. [Query] 方法必须改为 static。
2. 新增 Async ECS 执行模式。
```

但是它们对测试的影响范围不同：

```text id="nsdrsr"
[Query] static：
  会影响源生成器测试、Analyzer 测试、所有直接使用 [Query] 的测试类。

Async ECS：
  默认不开启，不应影响现有同步运行时测试。
```

最终目标：

```text id="kjh6ua"
现有运行时测试尽量不动。
所有 [Query] 生成器测试改成 static。
新增 Async ECS 独立测试集。
默认 Build() 仍然 Sync，避免线程时序污染现有测试。
```

---

# 1. 测试分层

测试分成四类。

```text id="o7cgca"
A. 纯运行时测试：
   不使用 [Query] 源生成器。
   直接手写 IQueryJob / IProjectionJob。
   默认 Sync 下尽量不改。

B. 源生成器测试：
   测试 [Query] / [Bring] / EntryPoint 生成代码。
   必须改成 static Query。

C. Analyzer / 诊断测试：
   新增“非 static Query 报错”。
   新增“Input / Component / Bring 参数顺序”诊断。

D. Async ECS 测试：
   显式开启 EcsExecutionMode.Async。
   测试 EcsWorker、MPSC、异步 Query、异步 Bring、ActorEvent 回流。
```

---

# 2. A 类：现有运行时测试尽量不动

## 2.1 QueryBringJobTests 可以基本不动

当前 `QueryBringJobTests` 里的纯 Query 测试是手写 `IQueryJob`，然后直接：

```csharp id="t3lv55"
runtime.EcsWorld
       .Query<JobPositionComponent, JobVelocityComponent>()
       .ForEach(ref job);
```

测试意图是验证纯 Query + Job ForEach 能修改 ECS 组件，并且不创建 Actor、不 Touch Actor、不 Post ActorEvent。

这个测试不依赖 `[Query]` 源生成器，所以不需要因为 static Query 改造而修改。

---

## 2.2 Bring Job 运行时测试也可以不动

当前 Bring Success 测试也是手写 `IProjectionJob3x1`，然后：

```csharp id="by1xvc"
runtime.EcsWorld
       .Query<JobPositionComponent, JobVelocityComponent, JobAoiComponent>()
       .Bring<JobMoveViewEvent>()
       .ForEach(ref job)
       .Batch()
       .Post();

runtime.Pump(0.016f);
```

测试验证 `ProjectResult.Success` 时会修改 ECS、Touch/Ensure Actor、Add Event 到 Batch、Post ActorEvent。

这个测试也不依赖 `[Query]` 源生成器，所以默认 Sync 下不应该改。

Touch / Fail 测试同理，它们验证的是 `ProjectResult.Touch` 和 `ProjectResult.Fail` 的运行时语义，不是生成器语义。

---

## 2.3 为什么默认 Sync 可以保护这些测试？

现有测试默认都是：

```csharp id="jsj3vr"
LayerHub.CreateLayers()
    .Push(new JobTestLayer())
    .Build();
```

`CreateRuntime()` 没有传任何 ECS 异步配置。

所以新功能加入后，默认必须是：

```text id="jp2zww"
EcsExecutionMode.Sync
不启动 EcsWorker
Query.ForEach 立即执行
Bring.Batch.Post 仍走当前同步行为
```

这样现有运行时测试保持稳定。

# 3. B 类：源生成器测试必须改成 static Query

所有使用 `[Query]` 的测试输入代码，都要从 instance 方法改成 static 方法。

## 3.1 普通 Query 测试修改

旧测试输入：

```csharp id="iok63z"
public sealed partial class MoveService : IService
{
    [Query]
    private void OnMove(ref Position position, in Velocity velocity)
    {
        position.X += velocity.X;
    }
}
```

新测试输入：

```csharp id="fdn7wx"
public sealed partial class MoveService : IService
{
    [Query]
    private static void OnMove(ref Position position, in Velocity velocity)
    {
        position.X += velocity.X;
    }
}
```

旧期望生成代码里可能有：

```csharp id="soexdl"
var job = new __MoveJob(this);
```

新期望必须变成：

```csharp id="inqw0n"
var job = new __MoveJob();
```

旧期望 Job 里可能有：

```csharp id="r55dlp"
private readonly MoveService _self;

public __MoveJob(MoveService self)
{
    _self = self;
}

public void Execute(...)
{
    _self.OnMove(ref c0, in c1);
}
```

新期望必须是：

```csharp id="v4hg64"
private readonly struct __MoveJob : IQueryJob<Position, Velocity>
{
    public void Execute(
        Entity entity,
        ref Position c0,
        in Velocity c1)
    {
        OnMove(ref c0, in c1);
    }
}
```

测试断言重点：

```text id="8e8n14"
生成代码不包含 _self。
生成代码不包含 new __MoveJob(this)。
生成代码不包含 _self.OnMove。
生成代码直接调用 static OnMove。
```

## 3.2 带输入参数的 Query 测试

新增测试输入：

```csharp id="eenzja"
public sealed partial class MoveService : IService
{
    [Query]
    private static void OnMove(
        float deltaTime,
        ref Position position,
        in Velocity velocity)
    {
        position.X += velocity.X * deltaTime;
    }
}
```

期望生成入口：

```csharp id="jzgbzm"
public void Move(float deltaTime)
{
    var job = new __MoveJob(deltaTime);

    global::LayerBase.ServiceECSExtensions
        .Query<Position, Velocity>(this)
        .ForEach(ref job);
}
```

期望生成 Job：

```csharp id="9in3jz"
private readonly struct __MoveJob : IQueryJob<Position, Velocity>
{
    private readonly float _deltaTime;

    public __MoveJob(float deltaTime)
    {
        _deltaTime = deltaTime;
    }

    public void Execute(
        Entity entity,
        ref Position c0,
        in Velocity c1)
    {
        OnMove(_deltaTime, ref c0, in c1);
    }
}
```

测试断言重点：

```text id="2skrh0"
入口方法带 deltaTime 参数。
Job 构造函数带 deltaTime。
Job 保存 readonly 字段。
Execute 调用 static OnMove，并传入 _deltaTime。
deltaTime 不进入 Query<T...> 泛型列表。
```

# 4. C 类：Analyzer / 诊断测试


```csharp id="qzxwxx"
        .ForEach(ref job);
```


# 7. 需要新增的测试辅助 API

异步测试最大问题是线程时序。不要在测试里写不稳定的 `Thread.Sleep(10)`。

建议新增 internal 测试辅助：

```csharp id="d78ybs"
internal interface IEcsSchedulerTestHook
{
    bool IsIdle { get; }

    void WaitIdleForTest(TimeSpan timeout);
}
```

Async Scheduler 实现：

```csharp id="lzft5p"
internal void WaitIdleForTest(TimeSpan timeout)
{
    SpinWait.SpinUntil(
        () => _workQueue.Count == 0 && _worker.IsExecuting == false,
        timeout);
}
```

更稳的是使用计数器：

```text id="d4gxf3"
SubmittedWorkCount
CompletedWorkCount
```

测试等待：

```csharp id="uc4vdu"
SpinWait.SpinUntil(
    () => CompletedWorkCount >= submittedFence.Sequence,
    timeout);
```

最好引入 `EcsFence`：

```csharp id="a4lhyc"
internal readonly struct EcsFence
{
    public readonly long Sequence;
}
```

调度返回 fence：

```csharp id="b8v74o"
EcsFence fence = EcsScheduler.Schedule(item);
```

虽然用户 API 不暴露 fence，但测试可以通过内部 hook 拿最近 sequence。

# 10. 最终测试策略结论

最终测试策略是：

```text id="ql2kwl"
破坏性改动集中在 [Query] 源生成器测试。
运行时旧测试通过默认 Sync 保护，尽量不动。
异步 ECS 作为显式新模式，用新增测试覆盖。
```

原则：

```text id="8dkbhy"
不保留 legacy instance Query。
不为了兼容旧写法引入历史包袱。
但也不让异步功能影响默认同步测试。
```

最后的测试矩阵应该是：

```text id="nxgdke"
Static Query + Sync：
  必须通过。

Static Query + Async：
  必须通过。

Manual IQueryJob + Sync：
  保持现有测试通过。

Manual IQueryJob + Async：
  作为新增测试覆盖。

Instance [Query]：
  必须报诊断，不能生成代码。
```
