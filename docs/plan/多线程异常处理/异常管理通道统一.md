# LayerBase `LayerExceptionHub` 独立融合设计方案

## 1. 设计目标

本次改造只解决一个问题：

```text
让 LayerBase 内部所有异常都通过 LayerExceptionHub 运输，
但保持原有 LayerHub 异常观察接口完全不变。
```

需要保持不变的公开接口：

```csharp
public static event Action<LayerEventInfo>? LayerHub.OnLayerEventInfo;

public event Action<LayerEventInfo>? LayerRuntime.OnLayerEventInfo;
```

现有用户代码无需修改：

```csharp
LayerHub.OnLayerEventInfo += info =>
{
    if (info.Type == LayerEventInfoType.Error)
    {
        Console.WriteLine(info.Exception);
    }
};
```

新的完整异常接口可以继续保留：

```csharp
runtime.ExceptionCallbacks.OnExceptionRecord += record =>
{
    // 获取 ScopeId、ServiceId、TraceId、ThreadId 等完整信息。
};
```

最终形成两个观察层级：

```text
兼容接口：
    LayerHub.OnLayerEventInfo
    LayerRuntime.OnLayerEventInfo

详细接口：
    LayerRuntime.ExceptionCallbacks.OnExceptionRecord
```

但两者必须来自同一条 `LayerExceptionHub` 内部通道。

---

# 2. 最终架构

```text
ScopeRuntime
ECS Worker
Job Worker
LBTask continuation
PostScheduler
TimeScheduler
Layer/Event Handler
        │
        │ Report LayerExceptionRecord
        ▼
LayerRuntime.ExceptionHub
        │
        │ owner thread Drain
        ▼
LayerRuntimeExceptionSink
        ├── ExceptionCallbacks.OnExceptionRecord
        ├── LayerRuntime.OnLayerEventInfo
        └── LayerHub.OnLayerEventInfo
```

所有权关系：

```text
LayerHub
    公开静态门面，不拥有正常 Runtime 的异常队列。

LayerRuntime
    拥有唯一 LayerExceptionHub。
    负责当前 Runtime 内所有 Scope 和 Worker 的异常。

ScopeRuntime
    捕获异常并上报所属 LayerRuntime.ExceptionHub。

LayerExceptionHub
    只负责线程安全运输与排空。
    不直接理解 LayerHub，也不直接调用 LayerHub。
```

核心原则：

```text
LayerExceptionHub 是运输层。
LayerRuntimeExceptionSink 是适配层。
LayerHub 是公开观察门面。
```

---

# 3. 为什么不能让 LayerHub 直接持有全局异常队列

LayerHub 当前管理多个 `LayerRuntime`。

如果所有 Runtime 共用一条全局异常队列，会产生：

```text
1. Runtime A 和 Runtime B 的异常所有权混乱。
2. Runtime 已销毁后，其异常仍可能在全局队列中。
3. 测试之间容易相互污染。
4. 无法精确停止某个 Runtime。
5. Scope 异常可能被错误地报告给 Primary Runtime。
```

因此正确模型必须是：

```text
Runtime A
    ExceptionHub A

Runtime B
    ExceptionHub B
```

`LayerHub.OnLayerEventInfo` 只作为最终统一广播入口。

# 4. 当前实现中需要修正的地方

## 4.1 ExceptionCallbacks 没有接入原接口

当前构造中创建了：

```csharp
ExceptionHub = new LayerExceptionHub();
ExceptionCallbacks = new LayerHubExceptionCallbacks();
```

Pump 时调用：

```csharp
ExceptionHub.DrainAndDispatch(ExceptionCallbacks);
```

但 `LayerHubExceptionCallbacks` 只触发自己的：

```csharp
OnExceptionRecord
OnException
OnExceptionQueueOverflow
```

没有调用：

```csharp
LayerRuntime.ReportInfo
```

因此不会自动进入：

```csharp
LayerRuntime.OnLayerEventInfo
LayerHub.OnLayerEventInfo
```

必须引入一个 Runtime 级 Sink 作为统一适配器。

---

## 4.2 旧异常仍绕过 ExceptionHub

当前 `LayerRuntime.ReportLayerEventError` 直接执行：

```csharp
ReportInfo(new LayerEventInfo(...));
```

意味着：

```text
旧 Layer/Event 异常
    直接调用用户委托

Scope 异常
    进入 LayerExceptionHub
```

这仍然是两条通道。

所有 `ReportLayerEventError` 都必须改成生成 `LayerExceptionRecord` 后进入 `ExceptionHub`。

---

## 4.3 静态 LayerHub 会错误使用 Primary Runtime

当前静态：

```csharp
LayerHub.ReportLayerEventError(...)
```

在存在 Primary Runtime 时，会把异常发给 Primary Runtime。

这在多 Runtime 下可能错误：

```text
Runtime B 的 Worker 抛异常
    ↓
LayerHub.ReportLayerEventError
    ↓
错误发送给 Primary Runtime A
```

必须优先从当前执行上下文确定所属 Runtime。

# 5. 新增 LayerRuntimeExceptionSink

这是融合方案的核心。

```csharp
internal sealed class LayerRuntimeExceptionSink :
    ILayerExceptionSink
{
    private readonly LayerRuntime _runtime;

    private readonly LayerHubExceptionCallbacks
        _detailedCallbacks;

    public LayerRuntimeExceptionSink(
        LayerRuntime runtime,
        LayerHubExceptionCallbacks detailedCallbacks)
    {
        // runtime：
        // 当前 LayerExceptionHub 所属的 Runtime。
        _runtime = runtime ??
            throw new ArgumentNullException(
                nameof(runtime));

        // detailedCallbacks：
        // 新版详细异常事件适配器。
        _detailedCallbacks = detailedCallbacks ??
            throw new ArgumentNullException(
                nameof(detailedCallbacks));
    }

    public void OnException(
        in LayerExceptionRecord record)
    {
        // 先触发新版详细异常回调。
        DispatchDetailedRecord(record);

        // 再转换成原 LayerEventInfo。
        LayerEventInfo legacyInfo =
            LayerExceptionInfoAdapter.ToLayerEventInfo(
                _runtime,
                record);

        // ReportInfo 保持原有公开语义：
        // 1. LayerRuntime.OnLayerEventInfo
        // 2. LayerHub.OnLayerEventInfo
        _runtime.ReportInfo(legacyInfo);
    }

    public void OnExceptionQueueOverflow(
        int droppedCount,
        in LayerExceptionRecord lastRecord)
    {
        DispatchDetailedOverflow(
            droppedCount,
            lastRecord);

        var overflowException =
            new LayerBaseQueueOverflowException(
                scopeId: lastRecord.ScopeId,
                queueKind:
                    LayerQueueKind.ExceptionQueue,
                capacity:
                    lastRecord.QueueCapacity,
                count: droppedCount);

        var overflowRecord =
            new LayerExceptionRecord(
                exception: overflowException,
                scopeId: lastRecord.ScopeId,
                serviceId: lastRecord.ServiceId,
                phase:
                    LayerExceptionPhase.QueueOverflow,
                queueKind:
                    LayerQueueKind.ExceptionQueue,
                messageId: lastRecord.MessageId,
                trace: lastRecord.Trace,
                threadId:
                    Environment.CurrentManagedThreadId,
                tick: lastRecord.Tick,
                queueCapacity:
                    lastRecord.QueueCapacity,
                queueCount: droppedCount);

        LayerEventInfo legacyInfo =
            LayerExceptionInfoAdapter.ToLayerEventInfo(
                _runtime,
                overflowRecord);

        _runtime.ReportInfo(legacyInfo);
    }

    private void DispatchDetailedRecord(
        in LayerExceptionRecord record)
    {
        try
        {
            ((ILayerExceptionSink)_detailedCallbacks)
                .OnException(record);
        }
        catch (Exception callbackException)
        {
            // 详细异常回调自身出错时，
            // 不能重新写入当前 ExceptionHub，
            // 否则可能形成递归异常循环。
            LayerHub.ReportEmergencyCallbackFailure(
                callbackException);
        }
    }

    private void DispatchDetailedOverflow(
        int droppedCount,
        in LayerExceptionRecord record)
    {
        try
        {
            ((ILayerExceptionSink)_detailedCallbacks)
                .OnExceptionQueueOverflow(
                    droppedCount,
                    record);
        }
        catch (Exception callbackException)
        {
            LayerHub.ReportEmergencyCallbackFailure(
                callbackException);
        }
    }
}
```

# 6. LayerExceptionRecord 到 LayerEventInfo 的适配器

原 `LayerEventInfo` 保持不变。

```csharp
internal static class LayerExceptionInfoAdapter
{
    public static LayerEventInfo ToLayerEventInfo(
        LayerRuntime runtime,
        in LayerExceptionRecord record)
    {
        string source =
            CreateSource(record);

        string eventName =
            CreateEventName(record);

        string message =
            CreateMessage(runtime, record);

        return new LayerEventInfo(
            layerIndex: -1,
            source: source,
            eventName: eventName,
            message: message,
            type: LayerEventInfoType.Error,
            exception: record.Exception);
    }

    private static string CreateSource(
        in LayerExceptionRecord record)
    {
        if (record.ServiceId >= 0)
        {
            return
                $"Scope[{record.ScopeId}]/" +
                $"Service[{record.ServiceId}]";
        }

        return $"Scope[{record.ScopeId}]";
    }

    private static string CreateEventName(
        in LayerExceptionRecord record)
    {
        if (record.MessageId >= 0)
        {
            return
                $"{record.Phase}:" +
                $"{record.MessageId}";
        }

        return record.Phase.ToString();
    }

    private static string CreateMessage(
        LayerRuntime runtime,
        in LayerExceptionRecord record)
    {
        return
            $"Runtime={runtime.Id}, " +
            $"Scope={record.ScopeId}, " +
            $"Service={record.ServiceId}, " +
            $"Phase={record.Phase}, " +
            $"Queue={record.QueueKind}, " +
            $"Thread={record.ThreadId}, " +
            $"Tick={record.Tick}, " +
            $"Trace={record.Trace.TraceId}, " +
            $"ParentTrace=" +
            $"{record.Trace.ParentTraceId}: " +
            record.Exception.Message;
    }
}
```

后续 Generator 可以生成：

```text
ScopeId -> ScopeName
ServiceId -> ServiceName
MessageId -> EventName / CallName
```

第一阶段不要求引入字典。

## 7.3 Pump 中统一排空

当前：

```csharp
ExceptionHub.DrainAndDispatch(
    ExceptionCallbacks);
```

改为：

```csharp
TryDrainExceptions();
```

实现：

```csharp
private void TryDrainExceptions()
{
    if (!IsOwnerThread)
    {
        return;
    }

    if (Interlocked.Exchange(
            ref _drainingExceptions,
            1) != 0)
    {
        return;
    }

    try
    {
        ExceptionHub.DrainAndDispatch(
            _exceptionSink);
    }
    finally
    {
        Volatile.Write(
            ref _drainingExceptions,
            0);
    }
}

private bool IsOwnerThread =>
    Environment.CurrentManagedThreadId ==
    _ownerThreadId;
```

# 8. 统一 Runtime 上报入口

新增：

```csharp
internal void ReportException(
    in LayerExceptionRecord record)
{
    ExceptionHub.Report(record);

    // 保持主线程同步异常的原有可观察性。
    //
    // 例如同步 Send handler 抛异常后，
    // 旧测试可能要求 Send 返回前就收到回调。
    if (IsOwnerThread)
    {
        TryDrainExceptions();
    }
}
```

Worker 线程调用时：

```text
只写入 ExceptionHub。
不会执行用户回调。
```

owner thread 调用时：

```text
写入 ExceptionHub。
立即在安全上下文 Drain。
保持同步异常的旧行为。
```

# 10. 正确解析异常所属 Runtime

静态异常入口不能继续默认使用 Primary Runtime。

## 10.1 第一优先级：ScopeExecution

当前 `ScopeExecution` 已经保存：

```csharp
ScopeExecution.Current.Runtime
```

因此：

```csharp
private static LayerRuntime?
    TryResolveCurrentRuntime()
{
    ScopeRuntime? scopeRuntime =
        ScopeExecution.Current.Runtime;

    if (scopeRuntime?.OwningRuntime
        is LayerRuntime scopeOwner)
    {
        return scopeOwner;
    }

    return
        LayerRuntimeExecution.CurrentRuntime;
}
```

---

## 10.2 第二优先级：RuntimeExecution

MainScope 或普通 Layer 执行时，可能没有 `ScopeExecution.Current`。

建议新增：

```csharp
internal static class LayerRuntimeExecution
{
    private static readonly
        AsyncLocal<LayerRuntime?>
        s_current = new();

    public static LayerRuntime?
        CurrentRuntime =>
        s_current.Value;

    public static IDisposable Enter(
        LayerRuntime runtime)
    {
        LayerRuntime? previous =
            s_current.Value;

        s_current.Value = runtime;

        return new PopToken(previous);
    }
}
```

`LayerRuntime.Pump`、同步事件分发、Worker 提交边界中进入该上下文。

---

## 10.3 静态兼容入口

```csharp
internal static void ReportLayerEventError(
    int layerIndex,
    string source,
    string eventName,
    Exception exception)
{
    LayerRuntime? runtime =
        TryResolveCurrentRuntime();

    if (runtime != null)
    {
        runtime.ReportLayerEventError(
            layerIndex,
            source,
            eventName,
            exception);

        return;
    }

    ReportEmergencyException(
        new LayerEventInfo(
            layerIndex,
            source,
            eventName,
            exception.Message,
            LayerEventInfoType.Error,
            exception));
}
```

不得再写：

```csharp
s_primaryRuntime
    ?.ReportLayerEventError(...);
```

# 11. 无 Runtime 归属时的应急通道

仍然可能出现：

```text
Runtime 构造阶段失败
Runtime 已经销毁
全局静态初始化异常
第三方 Worker 没有绑定 Runtime
异常回调本身再次异常
```

这类异常不能写进某个正常 Runtime 的 ExceptionHub。

建议 LayerHub 内部保留：

```csharp
private static readonly
    LayerEmergencyExceptionHub
    s_emergencyHub = new(capacity: 64);
```

应急通道只用于无归属异常。

```csharp
internal static void
    ReportEmergencyException(
        LayerEventInfo info)
{
    if (!s_emergencyHub.TryReport(info))
    {
        // 最后的兜底。
        try
        {
            Console.Error.WriteLine(
                info.ToString());
        }
        catch
        {
            // 最终路径不再抛异常。
        }
    }
}
```

`LayerHub.Pump` 可以排空它：

```csharp
public static void Pump(float deltaTime)
{
    s_emergencyHub.Drain(
        static info =>
            Internal_NotifyEvent(info));

    // 再 Pump Runtime。
}
```

应急通道不能替代 Runtime.ExceptionHub。

# 12. 修复 LayerExceptionHub 的线程安全缺口

## 12.1 当前 overflow 写入竞争

当前多个生产者可能同时执行：

```csharp
_lastOverflow = record;
```

`LayerExceptionRecord` 是较大的 struct，不能假设整个赋值是原子的。

建议：

```csharp
public sealed class LayerExceptionHub
{
    private readonly
        LockedBoundedRingQueue<
            LayerExceptionRecord>
        _queue;

    private readonly object
        _overflowGate = new();

    private int _overflowCount;
    private LayerExceptionRecord
        _lastOverflow;
    private bool _hasLastOverflow;

    public void Report(
        in LayerExceptionRecord record)
    {
        if (_queue.TryEnqueue(record))
        {
            return;
        }

        lock (_overflowGate)
        {
            _overflowCount++;
            _lastOverflow = record;
            _hasLastOverflow = true;
        }
    }
}
```

只有异常队列已经满时才进入锁，不影响正常路径。

---

## 12.2 Drain overflow 快照

```csharp
private bool TryTakeOverflow(
    out int count,
    out LayerExceptionRecord record)
{
    lock (_overflowGate)
    {
        if (!_hasLastOverflow)
        {
            count = 0;
            record = default;
            return false;
        }

        count = _overflowCount;
        record = _lastOverflow;

        _overflowCount = 0;
        _lastOverflow = default;
        _hasLastOverflow = false;

        return true;
    }
}
```

---

## 12.3 Sink 异常隔离

`DrainAndDispatch` 不应该因为 Sink 抛异常而停止排空。

```csharp
public void DrainAndDispatch(
    ILayerExceptionSink sink)
{
    while (_queue.TryDequeue(
               out LayerExceptionRecord record))
    {
        try
        {
            sink.OnException(record);
        }
        catch (Exception sinkException)
        {
            LayerHub
                .ReportEmergencyCallbackFailure(
                    sinkException);
        }
    }

    if (TryTakeOverflow(
            out int count,
            out LayerExceptionRecord
                lastRecord))
    {
        try
        {
            sink.OnExceptionQueueOverflow(
                count,
                lastRecord);
        }
        catch (Exception sinkException)
        {
            LayerHub
                .ReportEmergencyCallbackFailure(
                    sinkException);
        }
    }
}
```

注意：

```text
Sink 异常绝不能再次写入当前 LayerExceptionHub，
否则可能发生无限递归。
```

# 13. ScopeRuntime 接入规则

当前 `ScopeRuntime.ReportException` 已经把异常写入：

```csharp
OwningRuntime.ExceptionHub.Report(record);
```

方向正确。

建议改成：

```csharp
OwningRuntime.ReportException(record);
```

区别是：

```text
直接 ExceptionHub.Report：
    主线程异常也只能等下一次 Pump。

OwningRuntime.ReportException：
    Worker 只入队；
    owner thread 可以立即安全 Drain。
```

所以：

```csharp
private void ReportException(...)
{
    if (OwningRuntime == null)
    {
        LayerHub.ReportEmergencyException(...);
        return;
    }

    LayerExceptionRecord record =
        CreateExceptionRecord(...);

    OwningRuntime.ReportException(record);
}
```

# 14. ScopeRuntime 需要补齐的异常边界

当前已经捕获：

```text
ServiceStart
PostDispatch
CallDispatch
Continuation
WorkerLoop
```

还需要分别捕获：

```text
Timer.Tick
PostScheduler.Pump
IUpdate.Update
ActorWorld.Pump
EcsWorld.SweepProjectedActors
EcsScheduler.DrainResults
Service Dispose
Scope Stop
```

不要只用一个 WorkerLoop 外层 catch，因为外层 catch 会让整个 Scope 直接停止，也无法准确标记异常阶段。

示例：

```csharp
private void PumpServices()
{
    for (int i = 0;
         i < Services.Length;
         i++)
    {
        if (Services[i]
            is not IUpdate update)
        {
            continue;
        }

        try
        {
            update.Update();
        }
        catch (Exception exception)
        {
            ReportException(
                exception,
                serviceId: i,
                phase:
                    LayerExceptionPhase
                        .EcsSystemTick,
                queueKind:
                    LayerQueueKind.None,
                messageId: -1);

            ApplyExceptionPolicy(
                LayerExceptionPhase
                    .EcsSystemTick,
                exception);
        }
    }
}
```

建议增加更准确阶段：

```csharp
ServiceUpdate
ServiceFixedUpdate
ActorPump
EcsResultDrain
```

# 15. LayerTask / continuation 接入

当前 `ScopeRuntime` 的 continuation 队列仍然是：

```csharp
IBoundedQueue<Action>
```

但代码已经定义了：

```csharp
LayerContinuation
```

其中包含：

```text
Action
ServiceId
TaskId
Trace
```

应该将：

```csharp
IBoundedQueue<Action>
```

改成：

```csharp
IBoundedQueue<LayerContinuation>
```

执行：

```csharp
private void DrainContinuations()
{
    while (_continuations.TryDequeue(
               out LayerContinuation continuation))
    {
        try
        {
            continuation.Action();
        }
        catch (Exception exception)
        {
            ReportException(
                exception,
                serviceId:
                    continuation.ServiceId,
                phase:
                    LayerExceptionPhase
                        .Continuation,
                queueKind:
                    LayerQueueKind
                        .ContinuationQueue,
                messageId:
                    continuation.TaskId,
                trace:
                    continuation.Trace);

            ApplyExceptionPolicy(
                LayerExceptionPhase
                    .Continuation,
                exception);
        }
    }
}
```

否则异常通道虽统一，但 async 调试上下文仍然丢失。

# 16. RethrowOnMainScope

当前枚举已有：

```csharp
RethrowOnMainScope
```

但 ScopeRuntime 的策略 switch 尚未实现该分支。

建议不要把异常重新写入 ExceptionHub，而是把一个重新抛出 continuation 投到 MainScope。

```csharp
case LayerExceptionPolicy
    .RethrowOnMainScope:
{
    OwningRuntime?
        .PostExceptionRethrow(
            record.DispatchInfo);

    return;
}
```

```csharp
internal void PostExceptionRethrow(
    ExceptionDispatchInfo dispatchInfo)
{
    ScopeRuntime mainScope =
        ScopeHost?.MainScope
        ?? throw new InvalidOperationException(
            "MainScope is unavailable.");

    bool accepted =
        mainScope.TryEnqueueContinuation(
            new LayerContinuation(
                action:
                    dispatchInfo.Throw,
                serviceId: -1,
                taskId: -1,
                trace:
                    ScopeTrace.Empty));

    if (!accepted)
    {
        Environment.FailFast(
            "MainScope exception " +
            "rethrow queue is full.",
            dispatchInfo.SourceException);
    }
}
```

原则：

```text
ExceptionHub 负责记录。
MainScope continuation 负责开发期重新抛出。
```

避免同一异常反复进入 ExceptionHub。

# 17. 异常回调顺序

单个异常建议固定顺序：

```text
1. ExceptionCallbacks.OnExceptionRecord
2. ExceptionCallbacks.OnException
3. LayerRuntime.OnLayerEventInfo
4. LayerHub.OnLayerEventInfo
```

这样：

```text
详细观察器先获得原始完整上下文。
兼容观察器之后获得映射结果。
```

异常队列保持 FIFO 顺序。

不同线程同时 Report 的严格发生顺序无法完全保证，只保证：

```text
成功进入环形队列后的消费顺序。
```

# 18. 生命周期与停止顺序

Runtime Dispose 时不能直接丢弃所有待处理异常。

建议：

```text
1. 停止 Scope 新任务入口。
2. 停止 Worker。
3. Drain 各 Scope 最后异常。
4. Drain Runtime.ExceptionHub。
5. Dispose ExceptionCallbacks / Runtime。
6. 从 LayerHub 注销。
```

示意：

```csharp
public void Dispose()
{
    if (_disposed)
    {
        return;
    }

    _disposed = true;

    ScopeHost?.Stop();
    Worker.Dispose();

    TryDrainExceptions();

    ScopeHost?.Dispose();

    // 其他资源释放……

    LayerHub.Internal_Unregister(this);
}
```

如果 Dispose 不在 owner thread 调用：

```text
不能直接执行用户异常回调。
```

此时可以把最终排空推迟到 owner thread，或者只记录到 EmergencyHub。

# 22. 最终规则

```text
1. 每个 LayerRuntime 拥有独立 LayerExceptionHub。
2. 任意 Worker/Scope 只调用 Report，不直接调用用户异常回调。
3. LayerRuntime owner thread 负责 Drain。
4. Drain 使用 LayerRuntimeExceptionSink。
5. Sink 同时触发新详细接口和原 LayerEventInfo 接口。
6. LayerHub.OnLayerEventInfo 签名和使用方式完全不变。
7. 所有旧 ReportLayerEventError 也必须进入 ExceptionHub。
8. 静态入口不得默认把异常交给 Primary Runtime。
9. 无 Runtime 归属异常进入 EmergencyHub。
10. 异常回调自身异常不得重新进入同一 ExceptionHub。
```

# 23. 最终结论

最终应当把异常系统定义成：

```text
LayerExceptionHub
    是每个 LayerRuntime 的线程安全异常运输通道。

LayerRuntimeExceptionSink
    把完整 LayerExceptionRecord
    适配成旧 LayerEventInfo。

LayerHub.OnLayerEventInfo
    继续作为用户统一观察异常的公开接口。
```

这样既能保留原接口和使用习惯，又能让 Scope、LBTask、ECS、Worker 和 JobScheduler 真正共用同一套线程安全异常通道。
