# LayerBase Scope 异步调试与统一异常通道完整设计方案

## 0. 目标

Scope 模型引入后，LayerBase 会从单运行域变成多运行域架构：

```text
LayerRuntime
  ActorWorld
  LayerExceptionHub
  ScopeRuntime[0] MainScope
  ScopeRuntime[1] CombatScope
  ScopeRuntime[2] NetScope
  ScopeRuntime[N] ...
```

这会带来新的调试问题：

```text
1. 异常可能发生在任意 Scope 线程。
2. 异常可能发生在 Service 生命周期、Event、Post、Call、LayerTask continuation、TimeScheduler、ECS Query、ActorEvent Flush 等不同阶段。
3. await 后续代码可能不在抛异常的线程继续执行。
4. Worker 线程不能直接调用用户异常回调。
5. 有限环形队列可能满，队列满本身也必须成为可诊断事件。
6. 跨 Scope Call 链可能很长，如果没有 TraceId，很难知道异常来源。
```

本方案的目标是：

```text
1. 所有 Scope 异常统一进入 LayerExceptionHub。
2. Worker Scope 只上报异常，不直接调用用户回调。
3. LayerHub 异常回调改造成多线程安全模型。
4. 用户异常回调默认只在 MainScope / LayerRuntime 安全上下文执行。
5. Call handler 异常既要进入异常通道，也要 SetException 给 await 方。
6. LayerTask continuation 异常必须被捕获并带 Scope 上下文。
7. 队列满必须进入异常通道，不能静默丢。
8. 每条 Post / Call / Continuation 都携带 TraceId。
9. Diagnostics 能还原跨 Scope 调用链。
10. 热路径尽量使用生成 ID + 数组 + 有限环形队列，不依赖 Dictionary / ConcurrentQueue。
```

---

## 1. 设计原则

### 1.1 ScopeRuntime 是异常发生域

异常发生在哪个 Scope，就由哪个 `ScopeRuntime` 捕获并上报。

例如：

```text
CombatScope 的 Call handler 抛异常
  -> CombatScopeRuntime 捕获
  -> LayerExceptionHub.Report(record)

NetScope 的 TimeScheduler 抛异常
  -> NetScopeRuntime 捕获
  -> LayerExceptionHub.Report(record)

MainScope 的 continuation 抛异常
  -> MainScopeRuntime 捕获
  -> LayerExceptionHub.Report(record)
```

### 1.2 LayerRuntime 是异常汇聚域

`LayerRuntime` 持有唯一的 `LayerExceptionHub`。

```text
LayerRuntime
  LayerExceptionHub
  ScopeRuntime[]
```

所有 ScopeRuntime 都通过它上报异常。

### 1.3 LayerHub 回调不能在 Worker 线程直接触发

错误做法：

```csharp
catch (Exception ex)
{
    LayerHub.OnException(ex); // 错：可能在 Worker 线程调用用户代码
}
```

正确做法：

```csharp
catch (Exception ex)
{
    exceptionHub.Report(record); // 只入队，不调用用户代码
}
```

然后在 MainScope 或 LayerRuntime 主 Pump 中：

```csharp
exceptionHub.DrainAndDispatch(layerHubExceptionSink);
```

### 1.4 SetResult / SetException 不能直接执行 continuation

Call handler 在 CombatScope 完成后：

```text
CombatScope
  Promise.SetResult(result)
```

Promise 不能直接执行 MainScope continuation。

它只能：

```text
Promise.SetResult
  -> PostContinuation 到 await 捕获的 ScopeRuntime.ContinuationQueue
```

然后由对应 ScopeRuntime Pump continuation。

# 3. LayerExceptionHub

## 3.1 职责

`LayerExceptionHub` 是统一异常通道。

它负责：

```text
1. 允许任意 Scope / 任意线程 Report 异常。
2. 使用线程安全有限环形队列保存异常。
3. 不能在 Report 中执行用户回调。
4. 在 MainScope / LayerRuntime Pump 中 Drain。
5. Drain 时调用 LayerHub 异常回调。
6. 异常队列满时记录 overflowCount 和 lastOverflow。
```

---

## 3.2 接口设计

```csharp
public interface ILayerExceptionSink
{
    // OnException：
    // 统一异常回调。
    // 默认在 MainScope / LayerRuntime 主 Pump 中执行。
    void OnException(in LayerExceptionRecord record);

    // OnExceptionQueueOverflow：
    // 异常队列满时触发。
    void OnExceptionQueueOverflow(
        int droppedCount,
        in LayerExceptionRecord lastRecord);
}
```

---

## 3.3 LayerExceptionHub 实现

```csharp
public sealed class LayerExceptionHub
{
    // _queue：
    // 多线程安全有限环形队列。
    private readonly LockedBoundedRingQueue<LayerExceptionRecord> _queue;

    // _overflowCount：
    // 异常队列满时累计溢出数。
    private int _overflowCount;

    // _lastOverflow：
    // 最近一次因为异常队列满而无法入队的异常。
    private LayerExceptionRecord _lastOverflow;

    // _hasLastOverflow：
    // 是否存在 last overflow 记录。
    private int _hasLastOverflow;

    public LayerExceptionHub(int capacity)
    {
        _queue = new LockedBoundedRingQueue<LayerExceptionRecord>(capacity);
    }

    public void Report(in LayerExceptionRecord record)
    {
        // Report：
        // 可被任意线程调用。
        // 这里只能入队，不能调用用户回调。
        if (_queue.TryEnqueue(record))
        {
            return;
        }

        Interlocked.Increment(ref _overflowCount);
        _lastOverflow = record;
        Volatile.Write(ref _hasLastOverflow, 1);
    }

    public void DrainAndDispatch(ILayerExceptionSink sink)
    {
        // DrainAndDispatch：
        // 建议只在 MainScope 或 LayerRuntime 主线程调用。
        while (_queue.TryDequeue(out LayerExceptionRecord record))
        {
            sink.OnException(record);
        }

        int overflow = Interlocked.Exchange(ref _overflowCount, 0);

        if (overflow <= 0)
        {
            return;
        }

        if (Volatile.Read(ref _hasLastOverflow) == 1)
        {
            sink.OnExceptionQueueOverflow(
                overflow,
                _lastOverflow);

            Volatile.Write(ref _hasLastOverflow, 0);
        }
    }
}
```

# 4. LayerHub 异常回调改造

## 4.1 兼容旧接口

如果现在已有：

```csharp
LayerHub.OnException += exception => ...
```

可以保留，但内部不再直接由 Worker 调用。

新增更完整接口：

```csharp
public sealed class LayerHubExceptionCallbacks : ILayerExceptionSink
{
    // 旧接口：
    // 只给 Exception。
    public event Action<Exception>? OnException;

    // 新接口：
    // 给完整异常上下文。
    public event Action<LayerExceptionRecord>? OnExceptionRecord;

    // 队列满回调。
    public event Action<int, LayerExceptionRecord>? OnExceptionQueueOverflow;

    void ILayerExceptionSink.OnException(in LayerExceptionRecord record)
    {
        OnExceptionRecord?.Invoke(record);
        OnException?.Invoke(record.Exception);
    }

    void ILayerExceptionSink.OnExceptionQueueOverflow(
        int droppedCount,
        in LayerExceptionRecord lastRecord)
    {
        OnExceptionQueueOverflow?.Invoke(
            droppedCount,
            lastRecord);
    }
}
```

## 4.2 线程语义

必须写进文档：

```text
LayerHub.OnException / OnExceptionRecord 默认只在 MainScope / LayerRuntime 主线程调用。
Worker Scope 不直接调用 LayerHub 回调。
```

每个 ScopeRuntime 必须捕获以下边界：

## 5.1 ScopeRuntime.ReportException

`ScopeRuntime` 内部统一通过一个方法上报。

```csharp
private void ReportException(
    Exception exception,
    int serviceId,
    LayerExceptionPhase phase,
    LayerQueueKind queueKind,
    int messageId,
    ScopeTrace trace,
    int queueCapacity = 0,
    int queueCount = 0)
{
    var record = new LayerExceptionRecord(
        exception: exception,
        scopeId: ScopeId,
        serviceId: serviceId,
        phase: phase,
        queueKind: queueKind,
        messageId: messageId,
        trace: trace,
        threadId: Environment.CurrentManagedThreadId,
        tick: _timeScheduler.Tick,
        queueCapacity: queueCapacity,
        queueCount: queueCount);

    _ownerRuntime.ExceptionHub.Report(record);
}
```

这里 `_ownerRuntime` 是 `LayerRuntime` 引用，只用于运行时编排和异常上报，不表示 Service 归属。

Service 归属仍是 `ScopeRuntime`。

## 5.2 Service 生命周期异常

```csharp
private void StartServices()
{
    for (int i = 0; i < _services.Length; i++)
    {
        try
        {
            _services[i].OnStart();
        }
        catch (Exception ex)
        {
            ReportException(
                exception: ex,
                serviceId: i,
                phase: LayerExceptionPhase.ServiceStart,
                queueKind: LayerQueueKind.None,

                trace: ScopeTrace.Empty);

                LayerExceptionPhase.ServiceStart,
                ex);
        }
    }
}
```

```csharp
private void StopServices()

                exception: ex,
                serviceId: i,
                phase: LayerExceptionPhase.ServiceStop,
                queueKind: LayerQueueKind.None,
                messageId: -1,
                trace: ScopeTrace.Empty);

            ApplyExceptionPolicy(
                LayerExceptionPhase.ServiceStop,
                ex);
        }
    }
}
```

## 5.6 WorkerLoop 兜底异常

内部每个阶段都应捕获，但 WorkerLoop 仍然需要兜底：

```csharp
private void WorkerLoop()
{
    try
    {
        ExecuteInScope(StartServices);

        while (_running)
        {
            float deltaTime = _timeScheduler.GetDeltaTimeForWorker();

            ExecuteInScope(() =>
            {
                PumpInternal(deltaTime);
            });

            _timeScheduler.SleepIfNeeded();
        }

        ExecuteInScope(StopServices);
    }
    catch (Exception ex)
    {

            serviceId: -1,
            phase: LayerExceptionPhase.WorkerLoop,
            queueKind: LayerQueueKind.None,
            messageId: -1,
            trace: ScopeTrace.Empty);

        _running = false;
    }
}
```

# 6. 队列满诊断

有限环形队列满是必须处理的一级错误。

## 6.1 Post 队列满

Post 不等待结果，所以返回 bool。

```csharp
internal bool TryPostToScope(
    int targetScopeId,
    in ScopePostMessage message)
{
    ScopeRuntime target = _scopes[targetScopeId];

    if (target.TryPost(message))
    {
        return true;
    }

    var ex = new LayerBaseQueueOverflowException(
        scopeId: targetScopeId,
        queueKind: LayerQueueKind.PostInbox,
        capacity: target.PostInboxCapacity,
        count: target.PostInboxCount);

    ReportQueueOverflow(
        targetScopeId,
        LayerQueueKind.PostInbox,
        ex,
        message.Trace,
        message.EventId,
        target.PostInboxCapacity,
        target.PostInboxCount);

    return false;
}
```

## 6.2 Call 队列满

Call 等待结果，所以必须让 Promise 失败。

```csharp
internal LBTask<TResult> CallScope<TCall, TResult>(
    int targetScopeId,
    int callId,
    TCall call)
{
    ScopeTrace trace = CreateTraceForTarget(targetScopeId);

    var promise = new ScopePromise<TResult>(
        resumeScope: ScopeExecution.Current,
        trace: trace);

    var message = new ScopeCallMessage(
        callId: callId,
        payload: call!,
        promise: promise,
        trace: trace);

    ScopeRuntime target = _scopes[targetScopeId];

    if (!target.TryCall(message))
    {
        var ex = new LayerBaseQueueOverflowException(
            scopeId: targetScopeId,
            queueKind: LayerQueueKind.CallInbox,
            capacity: target.CallInboxCapacity,
            count: target.CallInboxCount);

        ReportQueueOverflow(
            targetScopeId,
            LayerQueueKind.CallInbox,
            ex,
            trace,
            callId,
            target.CallInboxCapacity,
            target.CallInboxCount);

        promise.SetException(ex);
    }

    return new LBTask<TResult>(promise);
}
```

# 7. 异常处理策略

## 7.1 LayerExceptionPolicy

```csharp
public enum LayerExceptionPolicy
{
    // 只上报，继续运行。
    ReportAndContinue,

    // 停止当前 Scope。
    StopScope,

    // 停止整个 LayerRuntime。
    StopRuntime,

    // 把异常投递到 MainScope 后重新抛出。
    // 开发期调试最有用。
    RethrowOnMainScope,

    // 立即终止进程。
    FailFast
}
```

## 7.3 策略推荐

```text
ServiceStartPolicy      = RethrowOnMainScope

ContinuationPolicy      = RethrowOnMainScope
EcsQueryPolicy          = RethrowOnMainScope

```

运行期：

```text

ContinuationPolicy      = StopScope
```

## 7.4 ApplyExceptionPolicy

```csharp
private void ApplyExceptionPolicy(
    LayerExceptionPhase phase,
    Exception exception)
{
    LayerExceptionPolicy policy =
        _exceptionOptions.GetPolicy(phase);

    switch (policy)
    {
        case LayerExceptionPolicy.ReportAndContinue:
            return;

        case LayerExceptionPolicy.StopScope:
            RequestStop();
            return;

        case LayerExceptionPolicy.StopRuntime:
            _ownerRuntime.RequestStop();
            return;

        case LayerExceptionPolicy.RethrowOnMainScope:
            _ownerRuntime.PostRethrowToMainScope(exception);
            return;

        case LayerExceptionPolicy.FailFast:
            Environment.FailFast(
                "LayerBase fatal exception.",
                exception);
            return;
    }
}
```

# 8. RethrowOnMainScope

开发期最需要这个能力。

Worker 线程异常不要直接抛，而是投递到 MainScope：

```csharp
internal void PostRethrowToMainScope(Exception exception)
{
    ExceptionDispatchInfo dispatchInfo =
        ExceptionDispatchInfo.Capture(exception);

    var continuation = new LayerContinuation(
        action: () => dispatchInfo.Throw(),
        serviceId: -1,
        taskId: -1,
        trace: ScopeTrace.Empty);

    _mainScope.TryPostContinuation(continuation);
}
```

效果：

```text
CombatScope 抛异常
  -> ExceptionHub 记录
  -> MainScope continuation 中重新抛出
  -> IDE / Unity Console / Godot 主线程日志可捕获
```

# 9. ScopePromise 与异常传播

## 9.1 Call handler 异常传播

Call handler 抛异常时：

```text
1. 目标 Scope 上报异常。
2. Promise.SetException(ex)。
3. await 方在自己的 Scope continuation 中重新抛出。
```

`ScopePromise<TResult>`：

```csharp
public sealed class ScopePromise<TResult> : IScopePromise
{
    private readonly object _gate = new object();

    private bool _completed;
    private TResult? _result;
    private Exception? _exception;
    private LayerContinuation? _continuation;

    public ScopeTrace Trace { get; }

    public ScopeThreadContext ResumeScope { get; }

    public ScopePromise(
        ScopeThreadContext resumeScope,
        ScopeTrace trace)
    {
        ResumeScope = resumeScope;
        Trace = trace;
    }

    public bool IsCompleted
    {
        get
        {
            lock (_gate)
            {
                return _completed;
            }
        }
    }

    public void OnCompleted(Action continuation)
    {
        var layerContinuation = new LayerContinuation(
            action: continuation,
            serviceId: ScopeExecution.CurrentServiceId,
            taskId: ScopeExecution.CurrentTaskId,
            trace: Trace);

        bool postNow;

        lock (_gate)
        {
            if (!_completed)
            {
                _continuation = layerContinuation;
                return;
            }

            postNow = true;
        }

        if (postNow)
        {
            ResumeScope.PostContinuation(layerContinuation);
        }
    }

    public void SetResult(TResult result)
    {
        LayerContinuation? continuation;

        lock (_gate)
        {
            if (_completed)
            {
                throw new InvalidOperationException(
                    "Promise already completed.");
            }

            _completed = true;
            _result = result;
            continuation = _continuation;
        }

        if (continuation.HasValue)
        {
            ResumeScope.PostContinuation(continuation.Value);
        }
    }

    public void SetException(Exception exception)
    {
        LayerContinuation? continuation;

        lock (_gate)
        {
            if (_completed)
            {
                throw new InvalidOperationException(
                    "Promise already completed.");
            }

            _completed = true;
            _exception = exception;
            continuation = _continuation;
        }

        if (continuation.HasValue)
        {
            ResumeScope.PostContinuation(continuation.Value);
        }
    }

    public TResult GetResult()
    {
        if (_exception is not null)
        {
            ExceptionDispatchInfo.Capture(_exception).Throw();
        }

        return _result!;
    }
}
```

# 10. ScopeExecution 调试上下文

`ScopeExecution` 不应只保存 ScopeId，还应保存当前调试上下文。

```csharp
public static class ScopeExecution
{
    [ThreadStatic]
    private static ScopeThreadContext? _currentScope;

    [ThreadStatic]
    private static int _currentServiceId;

    [ThreadStatic]
    private static int _currentTaskId;

    [ThreadStatic]
    private static ScopeTrace _currentTrace;

    public static ScopeThreadContext Current => _currentScope
        ?? throw new InvalidOperationException(
            "No active ScopeThreadContext.");

    public static int CurrentServiceId => _currentServiceId;

    public static int CurrentTaskId => _currentTaskId;

    public static ScopeTrace CurrentTrace => _currentTrace;

    internal static void Enter(
        ScopeThreadContext scope,
        int serviceId,
        int taskId,
        ScopeTrace trace)
    {
        _currentScope = scope;
        _currentServiceId = serviceId;
        _currentTaskId = taskId;
        _currentTrace = trace;
    }

    internal static void Exit()
    {
        _currentScope = null;
        _currentServiceId = -1;
        _currentTaskId = -1;
        _currentTrace = ScopeTrace.Empty;
    }
}
```

执行 Service handler 时：

```text
Enter(scopeContext, serviceId, taskId, trace)
try { handler(); }
finally { Exit(); }
```

# 13. 测试设计

## T1：Worker 异常不直接触发用户回调

目标：

```text
Worker 抛异常后，LayerHub.OnException 不在 Worker 线程执行。
```

流程：

```text
1. CombatScope 是 Worker。
2. CombatService.OnStart 抛异常。
3. ExceptionHub 记录异常。
4. LayerRuntime.MainPump Drain ExceptionHub。
```

断言：

```text
exceptionThrownThreadId == CombatScopeThreadId
callbackThreadId == MainScopeThreadId
record.ScopeId == CombatScopeId
record.Phase == ServiceStart
```

---

## T2：Call handler 异常进入异常通道并传给 await 方

流程：

```text
1. MainScope await CombatScope.Call。
2. CombatScope Call handler 抛 InvalidOperationException。
3. CombatScope ReportException。
4. Promise.SetException。
5. MainScope Pump continuation。
```

断言：

```text
ExceptionHub 收到 record。
record.Phase == CallDispatch。
record.ScopeId == CombatScopeId。
await 方重新抛 InvalidOperationException。
await 方 continuation 执行在 MainScope。
```


断言：

```text

record.ScopeId == MainScopeId。
```

# 15. 最终规则

```text
1. ScopeRuntime 捕获本 Scope 内所有异常。
2. Worker Scope 不直接调用 LayerHub 用户异常回调。
3. 所有异常进入 LayerExceptionHub。
4. LayerExceptionHub 默认由 MainScope / LayerRuntime 主 Pump Drain。
5. Call handler 异常同时 Report + Promise.SetException。
6. Continuation 异常必须被 ScopeRuntime 捕获。
7. 队列满必须作为 QueueOverflow 异常上报。
8. TraceId 必须贯穿 Post / Call / Promise / Continuation / ExceptionRecord。
9. 开发期支持 RethrowOnMainScope。
10. 运行期支持 ReportAndContinue / StopScope / StopRuntime / FailFast。
```

# 16. 一句话总结

LayerBase Scope 异步调试的核心不是“打印异常”，而是：

```text
把所有 Scope、Call、Post、LayerTask continuation、队列满、WorkerLoop 的异常，
统一变成带 ScopeId / ServiceId / Phase / TraceId / ThreadId / Tick 的 ExceptionRecord，
再通过线程安全 LayerExceptionHub 汇聚，
最后在 MainScope / LayerRuntime 安全上下文中统一回调。
```

这样 Scope 异步系统才不是黑盒。
